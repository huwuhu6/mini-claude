# 验证策略演进记录

这份文档记录 Agent 如何判断任务已经完成，以及验证能力如何避免反过来制造 Token 浪费。

## 1. 增加验证能力

早期方案通过语法检查、符号重命名验证和详细系统报告提高完成确定性。随后发现，验证规则过重时，Agent 可能在真正修改前提前规划 `verify.py`，把验证本身变成额外工作。

相关提交：`4ad3aeb`、`4c5e835`、`2ba8b00`、`d01d72e`。

## 2. 从“越多验证越安全”转向按风险验证

### 观察到的问题

- 低风险静态修改不需要复杂的全量验证；
- 验证工具描述过于具体，会诱导 Agent 提前设计实现步骤；
- 语义包装虽然能提高提示清晰度，但也可能增加上下文和工具调用。

### 演进

- 为低风险静态重构增加停止启发式；
- 为符号重命名增加 `scope` 和目标函数约束；
- 调整 Todo 和 system prompt，强调目标而不是提前规定实现路径；
- 最终移除部分内置语法检查工具，减少验证层和 Agent 自主判断的重复。

相关提交：`2e3f764`、`4ad3aeb`、`3d2a9a4`。

## 当前结论

验证策略不应追求“验证步骤越多越好”，而应根据修改风险选择最低充分验证。低风险任务应该尽快收敛，高风险任务才引入更强的符号、语法或行为验证。

## 待补实验

后续需要用固定任务比较不同验证策略的成功率、平均轮数、Token 消耗和错误漏检率，避免只凭单次 trace 判断策略优劣。
