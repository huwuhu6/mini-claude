## 4. 已确认的文档与实现冲突

**冲突 A：README 对 Resume CLI 的时间层错位。** `README.md` 前面的“本地 HITL 审批与恢复”明确列 `/resume` 和启动 `--resume`，后半段旧文本仍说 SQLite 没有 Resume CLI。`src/cli/hitl_commands.py` 及 7C 提交证明当前有 CLI 恢复入口，因此旧句属于历史残留，不作为当前状态结论。本套资料记录冲突，但遵循“只新增文档、不修改现有 README”约束。

**冲突 B：历史 `s_full.py` 与当前远程文件树。** README/`v1.0.0` 描述单文件原型约 740 行，然而本次远程 main 递归 tree 无此文件，最初提交的 `.gitignore` 还忽略 `s_full.py`。因此现有证据只能重建自模块化首版起的代码路径；若原型在本机或旧资料中，需补充原文件及原始 commit/时间线。绝不能凭“曾经的类名”补造单文件代码片段。

**冲突 C：设计稿与正式主线是否启用。** 早期多 Agent、Process Shadow/2PC、Skill/MCP/Plugin 可能在文档中出现架构设想、候选分支或实验目录。当前 `main` 明确冻结部分多 Agent，SQLite 模式拒绝后台/子代理；MCP 尚未见 Client/Server 实现。不能因为“概念高级”就把它们加入已落地主运行架构。

**冲突 D：历史评测收益和清理后的收益。** `task_013` 早期 66.6% Token 下降与清理后 28.4% 对照并非同一有效性等级；`task_014` 的 68.8% 属另一任务。当前不能主张“项目上下文整体下降约 68%”。旧的 26.3→19.7 轮次与 82.9→63.2 秒，仍缺完整出处。

**冲突 E：测试“通过”与部署验证。** 7C 历史报告为 646 passed、12 skipped、4 failed，新增 CLI 定向 45 项通过，依旧存在四项完整单测失败和平台不一致；没有付费模型/人工 TTY/Linux 全场景验收。不能将定向测试通过与生产验证等同。
